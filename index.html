About

One line runs through everything I have worked on: take a business question nobody has framed precisely yet, and turn it into something that answers it reliably every time it comes back. Phrase the question precisely enough to be wrong about, decide which data and tools can answer it, build the workflow that produces the answer, and stay accountable for the number at the end. When the same question keeps returning, the answer should be a reusable product rather than another one-off analysis.

Agent workflows. I have four LLM applications running live, and I handle product definition, data model, retrieval, tool design, guardrails, deployment, and the debugging that starts after launch. Social Memory Copilot is where the orchestration is most explicit: a gate decides whether a turn needs memory at all, queries are rewritten before hybrid retrieval, session state is kept apart from long-term memory, every retrieved memory is cited and traced, and any tool that writes or deletes can only propose an action for a person to confirm. I add agents or model calls only where they earn their latency; in the intent-routing project, a confidence threshold decides which requests a small model handles and which are handed off to a larger one.

How I Work

01 · Frame

From ambiguous question to structured workflow

Start from the decision the business needs to make, not from the model. Break it into sub-tasks, decide which need data, which need retrieval or tools, and which need a person to sign off, and agree on how the output will be judged before anything is built.

KPI Design Requirements Decision Frameworks
02 · Orchestrate

Agents with explicit routing, memory, and validation

Routing and control flow live in testable components rather than prompt conventions: a gate that decides when to retrieve, confidence-based handoff to a larger model, session state separated from long-term memory, per-user tool scoping, graceful fallback, and human confirmation before any side effect.

Planning & Routing Tool Use Memory Human-in-the-Loop
03 · Measure

Evaluation before claims

Every system gets a metric it can fail on: Recall@5 and MRR for retrieval, a precision target for routing thresholds, held-out classes for open-set classification, scenario runs against a baseline for simulation. Synthetic data is labelled as synthetic, and demos are not presented as production usage.

Recurring needs become reusable products

If a question comes back every week, it should become a tool: templated SQL and scripts in place of manual re-extraction, scheduled agents that assemble weekly research digests, and metric definitions that hold from one reporting cycle to the next.

Live MVP · Google ADK · Agent orchestration, memory and hybrid retrieval

Social Memory Copilot

I built Social Memory Copilot to solve a simple problem: remembering the context around a person, not just their name. It keeps track of the current contact, conversation goal, and pending action. A gate decides whether a turn needs memory; if it does, the query is rewritten, relevant preferences, events, and commitments are retrieved, and the answer cites them with a trace of why each was used. Write tools can only create a pending action, so nothing reaches the database until the user confirms, and that is enforced in code rather than in the prompt. It deliberately uses one main agent with explicit, testable pipeline stages instead of adding agents that only add latency.

Retrieval combines BM25 with pgvector/HNSW, followed by RRF and a lightweight reranker. On a small synthetic evaluation set, Recall@5 improved from 0.682 with either route alone to 0.889 with fusion and reranking. The project has 354 passing tests covering user isolation, prompt injection, tool schemas, fallback behavior, and HITL state changes. The live Vercel demo uses synthetic contacts and memories; I do not present it as production usage.

Model fine-tuning · Confidence-based routing and handoff

Chinese Intent Recognition & Confidence Routing

Fine-tuned a Chinese intent classifier on more than 11,000 dialogues across 50 intents, reaching 87% test accuracy. Ten additional intent classes were held out from training to test how the system behaves when a request falls outside the known taxonomy rather than assuming every input belongs somewhere.

I then turned the confidence threshold into a routing policy. At a 90% precision target, the smaller model can handle 94% of known requests; low-confidence cases go to a larger model. The error review also separates model uncertainty from taxonomy gaps and missing system context, which matters more to a product team than one aggregate score.

MS thesis · NLP and agent-based modelling

Sustainability Communication & Behavioral Modeling

Filtered 78,116 sustainability-related reviews out of the Yelp Open Dataset, ran LDA topic modelling in gensim with the topic count selected by coherence score rather than fixed by assumption, and scored sentiment with a pretrained multilingual BERT model. Those outputs then initialised 500 agents on a Barabási-Albert scale-free network in Mesa, where each agent only takes influence from neighbours whose views sit within a confidence threshold of its own. Three scenarios at ten seeds each over 100 steps, measured against a no-intervention baseline, turn a description of what people wrote into a question that can be tested: when does a sustainability narrative spread through a community, and when does it stall. Designed, implemented, and interpreted alone.

Alt-data method in progress · Free Sentinel-2 imagery

Orbital Capex

Hyperscaler AI capital expenditure is disclosed once a quarter. The construction sites are photographed from orbit every five days. This project measures built roof area and cleared ground at self-built US datacenter sites from free Sentinel-2 imagery, so that a quarterly, company-reported number can be checked against a weekly, self-collected one. Two findings shaped the method. NDBI, the standard built-up index, fails in reverse on the high-albedo membrane roofs these buildings use, excluding the newest construction precisely when the increment matters most. And grey metal roofing cannot be separated from dry bare soil in single-scene spectral space at all, so the pipeline separates them by temporal persistence instead, on the reasoning that a roof is permanent and a field is seasonal. Site boundaries come from county tax parcels queried by owner name and cross-checked against reported acreage, not from boxes drawn around an address. Status is openly Building. The pipeline runs end to end and the first parcel-clipped series does trend upward in step with the site's public construction timeline, but at 10 m the mask still takes in apron, parking and haul roads alongside roofing, so the level is not yet a roof-area figure and the method claims nothing until a timestamped prediction has been scored against reported capex.
